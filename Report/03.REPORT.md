## 3. 워크북

### 3.1 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

**4×4 마방진에서 행·열·양 대각선(10선)이 모두 34인지 판정하는 검증 규칙과 확인 루프를 만든다** — 대각선 누락으로 “맞췄다”고 착각해 20분을 쓰는 일을 줄이기 위함.

### 3.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | 4×4·빈칸 2(0)·1~16·합 34 과제를 푸는 **학습자** (검증 누락 → 채점 후 20분 손실을 겪은 당사자) |
| **Goal** | 채운 격자가 **행 4 + 열 4 + 대각선 2** 모두 합 34인지 **제출 전에** 한 번에 판정하고, 틀리면 **어느 축**이 깨졌는지 알 수 있게 한다 |
| **Input** | 4×4 정수 격자 (`0` = 빈칸, `1~16` = 채운 값; 중복·범위는 Rule로 제한) |
| **Output** | `pass` / `fail` + (fail 시) **깨진 축 목록** (예: `row2`, `diag_main`) — “완료” 착각·채점 후에야 알게 되는 상황 방지 |

### 3.3 성공 기준 3개 (Mom Test 증거와 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| 1 | 빈칸 2개를 채운 4×4 격자를 넣으면 **행·열·대각선 10축** 합 34를 **빠짐없이** 검사한다 | 「빈칸 2개 넣고 행·열·대각선 합 맞췄는데」→ **대각선 포함 전 축** 검증 |
| 2 | 대각선(또는 임의 축) 하나만 34가 아니어도 **fail**이며, “완료”로 처리하지 않는다 | 「대각선 하나를 빼먹어서」→ **부분 검증 통과 금지** |
| 3 | 검증 실패 시 **어느 축이 틀렸는지** 출력해, 채점 후 대각선만 다시 계산하며 **20분** 쓰는 재작업을 줄인다 | 「20분 날렸다」+ 채점 후 발견 → **제출 전 판정·재현** 가능 |

### 3.4 표면 문제 — 이번 프로젝트에서 하지 않을 것

| 하지 않음 (표면·솔루션) | 이유 |
|-------------------------|------|
| 빈칸 2개 **자동 풀이·완성 Solver** 전체 | 진짜 문제는 “풀이”가 아니라 **검증 누락·잘못된 완료** |
| **ECB 전체**·**GridUI / 앱** | 세션 3 범위 밖; 검증·루프 먼저 |
| 「마방진 **프로그램(솔버·UI) 만든다**」를 목표로 삼기 | Mom Test 표면 정의 |
| 행·열만 맞으면 통과하는 **불완전 검증** | 증거 2: 대각선 빼먹음이 20분 손실의 직접 원인 |
| 채점·제출 **시스템 연동** | 이번 세션은 **로컬 검증 루프**만 |

## 4. 8계층 — 이번 세션에서 만드는 것만

### 4.1 Rule (규칙)

- 격자는 **4×4**만 허용.
- 값: **0**(빈칸) 또는 **1~16**; 완성 판정 시 `0` 없음, 1~16 **중복 없음**.
- **합 34:** 각 **행 4개**, **열 4개**, **주대각선**, **부대각선** — 총 **10축** 모두 34.
- **완료(pass):** 10축 + 숫자 규칙을 **동시에** 만족. 하나라도 어기면 **fail**.

### 4.2 Command (명령)

| 명령 | 설명 |
|------|------|
| `validate(grid)` | 4×4 격자 전체 검증 → pass/fail + 실패 축 |
| `validate_axis(grid, axis)` | (선택) 특정 행/열/대각선만 재검 — “대각선만 다시 계산” 재현용 |
| `report_failures(result)` | fail 시 사람이 읽을 수 있는 축 목록 출력 |

### 4.3 (Skill) — 이번 세션 스킬

- **`SquareValidator` 스킬:** 4×4 입력 → 10축 합 34 검사 → 실패 축 식별.
- **판정 스킬:** “행·열만 맞음” ≠ pass — **대각선 2개 필수** 포함 (증거 2 반영).

### 4.4 Test Loop (테스트 루프)

```
[격자 입력] → validate → pass? → 종료(완료 인정)
                ↓ fail
         실패 축 확인 → 격자 수정 → validate (반복)
```

| 루프 단계 | 내용 |
|-----------|------|
| **Red** | 대각선만 틀린 격자 → **반드시 fail** (증거 2) |
| **Green** | 슬라이드 예시·빈칸 2개 채운 정답 격자 → **pass** (증거 1) |
| **회귀** | 행·열만 34인 **가짜 완료** 격자 → fail (20분 낭비 방지, 증거 3) |

**이번 세션에 만들지 않는 8계층 (참고):** Entity 상세, Boundary UI, `MissingFinder`, `Solver` 전체, Review Loop 등 — 후속 세션.
